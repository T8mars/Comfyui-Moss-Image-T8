# 第三批 20 轮交叉审查 · v0.1.4

本批使用新开的独立子 Agent，逐轮交换复现证据、修复和回归结果，不沿用前两批轮次。20 轮已完成，无已复现未处理问题。

## 修复

| 问题 | 处理 |
|---|---|
| loader 校验后、实际执行前的普通权重或 tokenizer 更新可绕过检查 | 描述符绑定校验时的包指纹；校验前后、装载前后及阶段正常返回前检查变化，要求重新加载 |
| 文件软链接的权重和 `.assets` 解析不一致 | 统一路径选择：优先逻辑路径旁已有侧车，否则使用真实目标旁侧车；损坏的逻辑侧车不静默回退 |
| 首轮大文件哈希不检查 Comfy Stop，装载期间取消仍可进入解码 | 哈希分块及模型构建、权重装载、参数转换、设备移动边界检查中断；装载后先检查再进入阶段 |
| 导出可读取已变化的源 shard，却沿用旧来源摘要 | 首次导出核对实际消耗的配置、索引、权重、scheduler 和 tokenizer；发布前复核来源文件身份 |
| 恢复时可能改坏配置摘要，或在拒绝不匹配版本前覆盖 tokenizer | 先检查目标版本、完整摘要及真实 header，再写侧车；恢复配置摘要从实际 header 计算 |
| 两个准备进程可将已成功的目标包改回未完成 | 目标从首次检查前持有进程锁，CLI 还锁定共用的模型与缓存目录；冲突明确拒绝，进程退出自动释放 |

文件统计绑定覆盖常规改动与原子替换，不保证检测刻意还原所有身份/时间信息的同文件改写。中断检查不能抢占已进入的单次磁盘读取、设备拷贝或计算内核。

首次导出增加实际源权重的摘要读取。已有包恢复仍校验目标权重完整 SHA，来源侧只读取真正消耗的小文件，不要求原始源 shard 或索引仍在。补丁回审时还发现并修正了 TE 权重摘要与 tokenizer 摘要变量复用的问题，补充 ready / pending 恢复后的完整摘要检查。

## 验证

新增绑定与取消回归均先复现失败，修复后通过。独立真实微型官方 DiT / Qwen3.5 复测确认：变动包被拒绝，不变文件的权重与输出保持一致，异常后阶段锁可继续使用。

本机 Windows 全量 **76 项通过、3 项文件软链接测试因权限明确跳过**，Node.js **4 项通过**；另在 [Linux CPU CI](https://github.com/T8mars/Comfyui-Moss-Image-T8/actions/runs/38917360922) 真实执行组件、取消、导出与进程锁子集，**27 项通过、无跳过**，包含上述 3 项软链接测试。中文/空格目录 junction 和 hardlink 也在本机独立验证。

新隔离 ComfyUI 服务实测 Base / SFT 各一张 **256×256、4 步**，均服务端完成、sampler 未缓存，PNG 尺寸、非恒定像素、内嵌参数及目视内容通过。SFT 与上一批同参数图逐像素一致，最大 RGB 差为 0。此处不计作新的 1024×1024、50 步验收，也不作为性能比较。
